# VINOS_ISO_SPEC.md — vinOS Live ISO & USB Specification

**Version:** 1.0
**Owner:** Vin Patel
**Depends on:** VINOS_SPEC.md (Milestones 1–4 must be green before starting this)
**Purpose:** Complete spec for Claude Code to produce a bootable vinOS live ISO via archiso, a CI pipeline that builds it, and a USB flashing procedure. The ISO must obey the Three Rules from VINOS_SPEC.md.

---

## 1. What the ISO is

A **live-boot vinOS** image flashed to USB:
- Boots to greetd → Hyprland with full vinOS branding, no installation required (try mode).
- Includes an installer path (`vinos-install-disk`) to put vinOS on the machine permanently.
- Built from the SAME vinos repo used by installer mode — the ISO is a compiled artifact of the repo, never a second source of truth. Any divergence between `curl | bash` vinOS and ISO vinOS is a bug.

Deliverables:
1. `iso/` directory in the vinos repo — a complete archiso profile.
2. `iso/build.sh` — one-command local build.
3. `.github/workflows/iso.yml` — CI build producing the ISO as a release artifact.
4. `iso/flash.sh` — guided, safety-checked USB flashing script.
5. `docs/USB.md` — human instructions (flash, boot, persistence).

## 2. Architecture: how the repo becomes an ISO

archiso builds an ISO from a **profile**: package list + `airootfs/` (files copied into the live system) + boot config. Our approach:

```
repo (source of truth)
   └── iso/profile/            ← starts as a copy of archiso's releng profile
         ├── packages.x86_64   ← base packages + everything 01/02 would install
         ├── airootfs/         ← receives repo configs + branding at build time
         ├── profiledef.sh     ← ISO name, label, publisher = vinOS / Vin Patel
         └── grub/ syslinux/ efiboot/  ← boot menus rebranded "vinOS"
```

**Build-time script execution model:** live ISOs can't run `install.sh` interactively at boot, and running pacman at first boot is slow and offline-hostile. Therefore:
- Package installation (scripts 01, 02) is TRANSLATED into `packages.x86_64` — `iso/gen-packages.sh` extracts every `install_pkg`/`install_aur` argument from `install/01-base.sh` and `install/02-desktop.sh` mechanically (grep/sed), so the package list can never drift from the scripts. AUR packages are pre-built in CI and dropped into a local repo included on the ISO (see §6).
- File/config/branding steps (scripts 03, 05) are executed INTO airootfs at build time by `iso/build.sh` using a `VINOS_ROOT` prefix variable: `common.sh` helpers must respect `VINOS_ROOT` (default `/`, set to the airootfs path during ISO builds). This is the only change permitted to lib/common.sh, and it must be backward-compatible.
- Service enablement (04) becomes static symlinks in `airootfs/etc/systemd/system/*.wants/` (archiso convention).

**Rule compliance:** the ISO build reads ONLY 01–05 from base plus any `--overlay` passed to `iso/build.sh` — so `vinos-edu` later gets its ISO with `iso/build.sh --overlay ../vinos-edu/overlay` and zero iso/ changes (Rule 2 payoff).

## 3. iso/profile specification

### 3.1 profiledef.sh
- `iso_name="vinos"`, `iso_label="VINOS_$(date +%Y%m)"`, `iso_publisher="Vin Patel <vinpatel.com>"`, `iso_application="vinOS Live"`, `iso_version` from repo VERSION file.
- Compression: `airootfs_image_type="squashfs"` with `-comp xz` (best size for USB).

### 3.2 packages.x86_64
- Generated by `iso/gen-packages.sh` (never hand-edited; CI fails if regenerating produces a diff).
- Plus live-only additions kept in `iso/packages.live`: `mkinitcpio-archiso`, `broadcom-wl` (optional), `intel-ucode`, `amd-ucode`, `networkmanager`, `gparted`.

### 3.3 airootfs/ contents (assembled by build.sh, not committed)
- Repo cloned to `airootfs/root/.local/share/vinos` AND `airootfs/etc/skel/.local/share/vinos` (so the live user has vinos-update etc.).
- Configs from `config/` copied to `airootfs/etc/skel/.config/` (skel so the live user gets them).
- Branding: os-release override, `/usr/share/vinos/logo/`, wallpaper — by running `05-branding.sh` with `VINOS_ROOT` set.
- Live user: `vin`, passwordless sudo (wheel + NOPASSWD), autologin via greetd config in airootfs (live mode only — the disk installer must NOT copy autologin).
- `vinos-install-disk` in `/usr/local/bin`: wraps `archinstall` with a vinOS preset JSON (Hyprland profile off — our scripts handle desktop; archinstall does disk/boot/user only, then chroot-runs `install.sh` from the bundled repo, fully offline via the ISO's package cache).

### 3.4 Boot menu branding (Rule 3 extended to ISO)
- GRUB/syslinux title: `vinOS Live (x86_64)`.
- Menu entries: `Boot vinOS`, `Boot vinOS (safe graphics — nomodeset)`, `Memtest`.
- Boot splash background: generate 640x480 PNG from `assets/logo/vinos.svg` at build time.

## 4. iso/build.sh specification

```
Usage: iso/build.sh [--overlay <path>]... [--out <dir>] [--skip-aur]
```
1. Preflight: running on Arch (or in Arch container), `archiso` installed, 15GB free in workdir, repo clean or warn.
2. Regenerate packages.x86_64 via gen-packages.sh; abort if git-diff shows drift (forces script/package sync).
3. Assemble airootfs per §3.3 (base + overlays in order; overlay configs shadow base — same semantics as install.sh).
4. Build local AUR repo if needed (§6) unless --skip-aur.
5. `mkarchiso -v -w <workdir> -o <outdir> iso/profile`.
6. Emit `vinos-<version>-x86_64.iso` + `sha256sums.txt`.
7. Idempotent: re-running cleans its own workdir first.

## 5. tests: iso/test.sh (QEMU acceptance)

Runs headless-capable QEMU checks; DONE WHEN all pass:
1. **Boot test:** `qemu-system-x86_64 -m 4G -smp 2 -cdrom <iso> -boot d` (UEFI via OVMF AND legacy BIOS — two runs). Pass = reaches graphical greeter within 120s (detect via serial console marker: add a systemd unit in airootfs that echoes `VINOS_BOOT_OK` to ttyS0 after graphical.target).
2. **Branding test:** guest `cat /etc/os-release` shows `ID=vinos` (via serial getty scripted login or a boot-time unit that dumps it to ttyS0).
3. **Identity of artifacts:** ISO filename, label, and grub title all carry the VERSION.
4. **Size budget:** ISO ≤ 3.5 GB (fail CI if exceeded — keeps 8GB USBs viable with room for persistence).
5. **RAM floor:** boot test repeated with `-m 3G` must still pass (live squashfs + Hyprland headroom check).

---

## 6. AUR handling (offline-safe)

Live ISOs can't makepkg at boot. Any AUR package referenced by 01/02:
1. CI job builds it in a clean Arch container with `makepkg`.
2. Outputs go to `iso/aurrepo/` with `repo-add vinos-aur.db.tar.gz *.pkg.tar.zst`.
3. Profile's `pacman.conf` gains `[vinos-aur]` file:// repo so mkarchiso installs them like normal packages.
4. Keep AUR dependencies MINIMAL — each one adds CI time. If a package has an official-repo alternative, prefer it.

## 7. CI pipeline (.github/workflows/iso.yml)

- Trigger: tag push `v*` + manual dispatch.
- Runner: `ubuntu-latest` with `container: archlinux:latest` (privileged not available on GH-hosted — mkarchiso needs loop devices, so use the documented workaround: run mkarchiso inside the container with `--privileged` via a self-hosted runner **on the Dell T430 (omarchyserver)** — this is the primary path; GH-hosted is fallback for lint/gen-packages checks only).
- Jobs:
  1. `lint`: shellcheck all scripts; gen-packages drift check.
  2. `aur`: build AUR packages, cache by PKGBUILD hash.
  3. `iso`: (self-hosted, Dell) run build.sh, run iso/test.sh QEMU suite, upload ISO + sha256 as release assets.
- Artifact retention: attach to GitHub Release on tags; 7-day artifact on manual runs.

## 8. USB flashing: iso/flash.sh + persistence

### flash.sh (safety-first)
1. `lsblk -d -o NAME,SIZE,MODEL,TRAN` and require the user to type the device name AND confirm by typing the model string (prevents the classic dd-onto-your-nvme disaster).
2. Refuse any device that is mounted at `/`, `/home`, or `/boot`, or is not `tran=usb` (override flag `--i-know-what-im-doing` for edge cases).
3. `dd if=<iso> of=/dev/<dev> bs=4M status=progress oflag=direct conv=fsync` then `sync`.
4. Offer persistence setup (below) as a post-step.

### Persistence (optional, default off)
- After flashing, remaining USB space → ext4 partition labeled `vinos-persist`.
- Kernel cmdline entry `Boot vinOS (persistent)` adds `cow_device=/dev/disk/by-label/vinos-persist` (archiso's persistent COW support).
- Document clearly in docs/USB.md: persistence stores changes (wifi passwords, files) across reboots; without it the USB is stateless.

### docs/USB.md contents
- Minimum hardware: x86_64, 4 GB RAM (3 GB floor), UEFI or BIOS.
- Flash instructions: flash.sh on Linux; balenaEtcher/Rufus (dd mode) on other OSes.
- Boot key cheat-sheet (F12/F2/Del common vendors).
- Try vs install vs persistent modes.

## 10. Conventions & guardrails

- Never hand-edit generated files (packages.x86_64, airootfs assembly) — fix the generator.
- All build steps runnable in a container; nothing may require the host to BE vinOS.
- ISO must work 100% offline after boot (no first-boot downloads).
- `vinos-install-disk` must show an explicit red warning + double confirmation before partitioning.
- Version everything: ISO label, grub title, os-release, filename all read the single VERSION file.

## 11. Out of scope

Secure Boot signing, 32-bit/ARM images, Ventoy multi-boot packaging, vinos-edu content payload (its ISO reuses this pipeline with `--overlay`; model/Kiwix placement gets its own spec).
