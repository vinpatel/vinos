## 1. Base system

- **Distribution:** Arch Linux (rolling), built via archiso `releng`-derived profile
- **Bootstrap tarball packages** (`iso/profile/bootstrap_packages`):
  - `arch-install-scripts`
  - `base`
- **Bootstrap compression:** `zstd -c -T0 --auto-threads=logical --long -19`
- **Root filesystem image type:** `squashfs`
- **Squashfs compression:** `xz` with BCJ x86 filter, 1 MB blocks, 1 MB dictionary
- **Install directory:** `arch`
- **Build modes:** `iso` (single-file live media)
- **Boot modes:** `bios.syslinux` + `uefi.systemd-boot`

**No third-party repos in the ISO's `pacman.conf`.** The `[vinos-aur]` repo is added *dynamically* by `iso/build.sh` only when `iso/aur.list` yields built packages, then removed for downstream image use.

**Build environment:** `docker run --rm --privileged archlinux:latest` runs `mkarchiso`. Host machine stays untouched. `/dev/kvm` passed through when available for 10× QEMU speedup during acceptance tests.

## 2. Kernels

Dual-kernel image. `systemd-boot` UEFI menu chooses which loads. Both kernels ship on the same ISO.

| Kernel | Package | Purpose | Boot entry file |
|---|---|---|---|
| Stock Arch | `linux` | Intel / AMD / generic PC | `01-archiso-linux.conf` |
| T2 Mac | `linux-t2` + `linux-t2-headers` (AUR) | 2018-2020 MacBook Pro/Air/iMac Pro | `00-archiso-t2-linux.conf` |

### Firmware bundle
`linux-firmware`, `linux-firmware-marvell`, `apple-bcm-firmware`, `apple-t2-audio-config`, `sof-firmware`, `alsa-firmware`

### Microcode
`intel-ucode`, `amd-ucode`

### DKMS modules
- `nvidia-open-dkms` + `nvidia-utils` (NVIDIA GPU support)
- `macbook12-spi-driver-dkms` (T2 trackpad + keyboard SPI driver)

### Initramfs presets
- `/etc/mkinitcpio.d/linux.preset` — stock kernel, archiso hooks
- `/etc/mkinitcpio.d/linux-t2.preset` — mirrors linux.preset for the T2 kernel, emits `initramfs-linux-t2.img`
- `/etc/mkinitcpio.conf.d/archiso.conf` — archiso hooks + T2 wifi/input MODULES

### T2 hardware tuning drop-ins
Committed under `iso/profile/airootfs/etc/`:
- `modprobe.d/broadcom-wl.conf`
- `modprobe.d/vinos-brcmfmac.conf` — the T2 wifi recipe (`feature_disable`, roam_off, no-anqp, MAC randomization off)
- `modprobe.d/vinos-hid-apple.conf` — Apple keyboard fnmode
- `modprobe.d/vinos-no-floppy.conf` — block phantom floppy detection
- `modules-load.d/vinos-t2.conf` — force-load `apple-bce` + `brcmfmac`

## 3. Boot creation

**7 boot entries** across BIOS + UEFI, unified in appearance:

### UEFI (`iso/profile/efiboot/loader/entries/`)

| sort-key | Title | Kernel | Distinguishing options |
|---|---|---|---|
| 00 | **➜ vinOS — Apple T2 Mac** | `linux-t2` | `intel_iommu=on iommu=pt cfg80211.ieee80211_regdom=US modprobe.blacklist=floppy` |
| 00-a | ➜ vinOS — T2 + persistence | `linux-t2` | + `cow_device=/dev/disk/by-label/vinos-persist` |
| 01 | vinOS — Intel / AMD / generic PC | `linux` | `quiet splash loglevel=3 vt.global_cursor_default=0` |
| 02 | vinOS — Intel/AMD + persistence | `linux` | + persistent `cow_device` |
| 02 | Boot vinOS with speech | `linux` | `accessibility=on` (BRLTTY assistive audio) |
| 03 | vinOS — persistent (Intel/AMD, USB persistence) | `linux` | persistence variant |
| 03 | Memtest86+ | — | EFI binary |

**Boot default:** the T2 entry (sort-key 00). Rationale: T2 Macs are the primary target hardware; generic Intel/AMD PCs boot fine on either entry.

**No boot entry hard-requires persistence.** Persistence entries are optional siblings that mount `/dev/disk/by-label/vinos-persist` as archiso's copy-on-write device.

### BIOS (`iso/profile/syslinux/`)

Standard archiso `syslinux.cfg` → `whichsys.c32` picker → `archiso_sys.cfg` for physical media, `archiso_pxe.cfg` for PXE boot. No vinOS-specific modifications.

## 5. Live user + session

**Live user:** `vinos` (uid dynamically assigned)
- Groups: `wheel`
- Shell: `/bin/bash`
- Password: empty (`passwd -d vinos`)
- Home: `/home/vinos` (seeded from `/etc/skel` on first boot)

**Creation:** `vinos-live-init.service` (from `iso/airootfs-overlay/etc/systemd/system/`) runs once at first boot:
1. If `vinos` user doesn't exist → `useradd -m -G wheel -s /bin/bash`
2. `passwd -d vinos` (empty password → passwordless sudo)
3. `cp -aRT /etc/skel /home/vinos/` (populate config)
4. `chown -R vinos:vinos /home/vinos`
5. Touch `/home/vinos/.vinos-live-init-done` so the service is a no-op on subsequent boots

**Session:** `greetd` autologin (no prompt) → `uwsm start hyprland-uwsm.desktop` → Hyprland Wayland session on tty1.

`greetd` config at `iso/airootfs-overlay/etc/greetd/config.toml`:
```
[terminal]
vt = 1
[default_session]
command = "uwsm start hyprland-uwsm.desktop"
user = "vinos"
[initial_session]
command = "uwsm start hyprland-uwsm.desktop"
user = "vinos"
```

`getty@tty1` autologin is explicitly disabled via `iso/airootfs-overlay/etc/systemd/system/getty@tty1.service.d/vinos-no-autologin.conf` — greetd is authoritative for tty1.

**sudoers:** `iso/airootfs-overlay/etc/sudoers.d/10-vinos-wheel` gives wheel group NOPASSWD sudo on the live session.

## 6. Desktop UX

### 6a. Hyprland configuration

**Primary file:** `config/hypr/hyprland.conf` — installed to `/etc/skel/.config/hypr/hyprland.conf` at build time, then to `/home/vinos/.config/hypr/hyprland.conf` on first boot via the live-init service.

**Design principle:** everything inline in a single file. Modular subdirs (`bindings/`, `apps/`, `toggles/`, `plugins.conf`) exist in the repo but are NOT sourced by default because they had version-dependent syntax that broke on the shipped Hyprland at build time. The v1.2.0 milestone activates the modular structure.

**Layout:** `dwindle` (BSP-style tiling)
- Gaps: `gaps_in = 6`, `gaps_out = 14`
- Border: `border_size = 2`, gradient `#33ccff → #bb9af7` @ 45° (vinOS teal → purple)
- Rounding: `12`
- Blur: on (size 6, 3 passes), inactive opacity 0.96

**Environment:**
- `XCURSOR_SIZE=24`, `HYPRCURSOR_SIZE=24`

## 7. UX helper library — the `vinos-*` command family

v1.1.0 ships **88 shell helper scripts** in `bin/vinos-*`, each installed to `/usr/share/vinos/bin/` and symlinked from `/usr/local/bin/` via `install/05-branding.sh`. Every script has execute permission enforced by `iso/profile/profiledef.sh:file_permissions`.

**Categories:**
- **AI:** `vinos-ai`, `vinos-first-run`, `vinos-menu`, `vinos-cheatsheet`
- **Hardware queries:** `vinos-ac-present`, `vinos-battery-*` (capacity, present, remaining-time, status), `vinos-brightness-*` (display, display-apple, keyboard, keyboard-mute), `vinos-audio-input-mute`, `vinos-audio-output-switch`
- **Diagnostics:** `vinos-doctor`, `vinos-hw-report`, `vinos-hw-hints`, `vinos-hw-external-monitors`, `vinos-hw-touchpad`
- **Compositor toggles:** `vinos-hyprland-monitor-*` (focused, focused-apple, internal, internal-mirror, scaling-cycle, watch), `vinos-hyprland-toggle`, `vinos-hyprland-toggle-disabled/enabled`, `vinos-hyprland-window-*` (close-all, gaps-toggle, pop, single-square-aspect-toggle, transparency-toggle), `vinos-hyprland-workspace-layout-toggle`
- **Capture:** `vinos-capture-screenshot`, `vinos-capture-text-extraction`
- **Hooks:** `vinos-hook`, `vinos-hook-install`
- **Utility:** `vinos-cmd-present`, `vinos-cmd-terminal-cwd`

**Design pattern:** every script is standalone bash, no shared runtime, `set -euo pipefail`, POSIX-friendly. Reads state from `/proc`, `/sys`, `hyprctl`, `notify-send`.

## 8. Live-only overlay

`iso/airootfs-overlay/` is rsync'd into `iso/profile/airootfs/` AFTER the installer scripts populate the tree — this is where live-ISO-only tweaks go:

- `etc/greetd/config.toml` — autologin the `vinos` user
- `etc/systemd/system/vinos-live-init.service` — creates the vinos user, seeds `/home/vinos` from `/etc/skel`
- `etc/systemd/system/getty@tty1.service.d/vinos-no-autologin.conf` — disables getty autologin
- `etc/systemd/system/multi-user.target.wants/vinos-live-init.service` — enables live-init
- `etc/systemd/system/multi-user.target.wants/avahi-daemon.service` — enables avahi
- `etc/systemd/system/multi-user.target.wants/cups-browsed.service` — enables cups-browsed
- `etc/systemd/system/sockets.target.wants/cups.socket` — enables cups
- `etc/systemd/system/sshd.service` — SSH daemon
- `etc/systemd/system/systemd-time-wait-sync.service` — wait for time sync
- `etc/nsswitch.conf` — mdns lookup
- `etc/sudoers.d/10-vinos-wheel` — wheel NOPASSWD

## 9. Build pipeline

`iso/build.sh` is the single entry point:

```
iso/build.sh
  ├── reads REPO/VERSION → VINOS_VERSION
  └── docker run --rm --privileged archlinux:latest bash -euo pipefail -c '
        ├── cp -a /vinos-src /vinos                   # working copy
        ├── bash iso/gen-packages.sh                  # regenerate packages.x86_64
        ├── export VINOS_ROOT=/vinos/iso/profile/airootfs
        ├── bash install/03-configs.sh                # copy config/ into skel
        ├── bash install/05-branding.sh               # os-release, wallpaper, vinos-* bins, plymouth theme
        ├── bash install/02-desktop.sh                # desktop package set + plymouth hook
        ├── bash install/04-services.sh               # enable systemd units
        ├── rsync -a iso/airootfs-overlay/ airootfs/  # live-only extras
        ├── (if aur.list non-empty) bash iso/aur-build.sh   # build [vinos-aur] local repo
        ├── mkarchiso -v -w WORK_DIR -o /out iso/profile
        └── sha256sum output.iso > sha256sums.txt
'
```

**Requirements:**
- `docker` (or `podman` with the docker CLI shim)
- ~15 GB scratch space
- `/dev/kvm` (optional, ~10× speed boost for QEMU tests)
- First build fetches ~800 MB of packages; subsequent builds hit the pacman cache mounted from host

**Output:** `iso/out/vinos-<VERSION>-x86_64.iso` + `iso/out/sha256sums.txt`

## 10. QA + ship-gate

**In v1.1.0:**
- `iso/test.sh` — QEMU acceptance harness with modes: `bios`, `uefi`, `both`, `matrix`. Asserts: `VINOS_BOOT_OK` marker reached, `/etc/os-release ID=vinos`, ISO filename + label carry VERSION, ISO size ≤ 3.5 GB, boot passes at 3 GB RAM floor
- `iso/test-desktop.sh` — headless screendump of settled desktop
- `iso/test-plymouth.sh` — Plymouth theme verification
- `iso/qemu-desktop.sh` — interactive QEMU window for manual testing
- `iso/flash.sh` — safe USB burn helper (refuses non-USB, requires double-typed confirmation)

**Introduced after v1.1.0** (not in this baseline; noted for context):
- `iso/qa/oneshot.sh` — the mandatory pre-flash gate (Layer 1 static + Layer 2 container + QEMU screendumps + regression harness)
- `iso/qa/verify-shipped-iso.sh` — regression harness asserting every past fix is intact

## 11. What the ISO does *not* include

Deliberate omissions in v1.1.0:

- **No install-to-disk from the live ISO.** The primary install path is `docs/INSTALL.md`: install Arch, then run the vinOS one-liner on top. Install-to-disk was added post-1.1.0.
- **No LUKS installer.** Full-disk encryption during install ships in a later milestone.
- **No pre-installed Claude Code / Ollama.** The Hyprland bindings expect these but note "needs `vinos-install-ai` first."
- **No agentic worker service.** `vinos-agent-worker` ships in v1.2.0 with the `vinos-vm` persona.
- **No Omarchy code.** v1.1.0 predates and rejects the Omarchy pivot direction. Every desktop component is assembled directly from Arch packages with vinOS-authored configs.

Any future build claiming to "reset to the 1.1.0 baseline" can be verified by:

```bash
# 1. Check the ISO byte-for-byte
sha256sum iso/out/vinos-1.1.0-x86_64.iso
# expected: 3bd3657ecbab018f1efe787c45caa83a28a6c19cbceaafa8ee009becd3873ef2

# 2. Check the git tag SHA
git rev-parse v1.1.0
# expected: 8bf79af1b2696698849506e831d3b347c004af5f

# 3. Check the commit the tag points at
git rev-parse v1.1.0^{commit}
# expected: e5c44b9e61e1e5e0819600e4f833d47322ff17ed
```

If any of these three values change, this document is out of sync with reality — investigate before trusting the "baseline" claim.
